# ProjectStatusReport v0.8.0

## Conditional output mode

v0.8.0 adds a second primary output path for projects that maintain ОСП directly in Confluence.

### When previous Confluence Storage Format is supplied

The skill switches to `confluence_storage` mode:

- previous Storage Format becomes the structural template;
- output is `confluence-storage.xml`;
- dedicated dates are rendered as native `<time datetime="YYYY-MM-DD" />`;
- inherited Handy Status macros are preserved/reused using existing numeric `id` values from the previous page;
- Handy `Status` text is not treated as authoritative;
- four-page DOCX pagination is not required;
- the user manually pastes the resulting Storage Format into Confluence Source Editor.

### When Storage Format is not supplied

Behavior remains compatible with v0.7.0:

- previous DOCX remains the structural template;
- output is working + clean DOCX;
- exactly four A4 landscape pages;
- existing validation and visual QA remain mandatory.

### Both formats

If the user explicitly requests both, both are generated independently from the same normalized report data.

## Safety rules for Handy Status

- Never invent Handy numeric IDs.
- Separate ID pools by semantic domain.
- Preserve the exact macro for unchanged continuing rows.
- If the same ID has conflicting textual labels, treat those labels as stale/unreliable.
- If a required Handy value cannot be safely mapped from the previous template, use readable text plus a `HANDY_STATUS_ID_REQUIRED` XML comment rather than fabricating a status.
