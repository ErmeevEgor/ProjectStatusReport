# ProjectStatusReport v0.9.0

## Главное изменение

v0.9.0 делает каноническим один рабочий сценарий:

**Web LLM + Google Drive project folder + persistent state + previous Confluence Storage Format XML → updated state in Drive + new Storage XML in chat.**

## Вход

- папка проекта Google Drive;
- проектные материалы/контекст и ссылки;
- `report-data.json`;
- `sources.json`;
- предыдущий ОСП в Confluence Storage Format XML/XHTML.

## Выход

- `report-data.json` обновляется в той же папке Google Drive;
- `sources.json` обновляется в той же папке Google Drive;
- `ОСП_<N>_Confluence_Storage_Format.xml` возвращается пользователю для ручной вставки через Confluence Source Editor.

XML по умолчанию не загружается в Drive.

## Удалено из канонического portable workflow

- DOCX output/fallback;
- working/clean DOCX;
- four-page validation;
- DOCX → Confluence conversion;
- `source-manifest.json` для web workflow;
- automatic Confluence publishing;
- local-agent branch as a primary scenario.

## State

`report-data.json` и `sources.json` считаются long-lived project state и должны обновляться на месте по существующим Drive file IDs без создания дублей.

## Confluence

- предыдущий Storage Format — основной structural/macro template;
- dedicated dates используют native `<time datetime="YYYY-MM-DD" />`;
- Handy Status numeric IDs никогда не придумываются;
- новые `ac:macro-id` для новых macro occurrences — уникальные UUID v4;
- XML формируется напрямую без DOCX intermediate.

## Build

Portable release builder больше не синхронизирует legacy Python runtime и wrapper scripts внутрь portable skill archive.
