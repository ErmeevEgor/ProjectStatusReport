# Трассировка источников

## Цель

Основной ОСП должен выглядеть как нормальный отчет, а не как техническая справка. При этом по каждому важному факту должна сохраняться возможность понять, откуда он взят.

## Формат source record

```json
{
  "id": "src-001",
  "type": "additional_agreement",
  "name": "ДС №1",
  "date": "2026-06-25",
  "reference": "п. 3.2 / Приложение 1",
  "note": "Стоимость этапа 1 010 000 руб.",
  "confidence": "confirmed"
}
```

## Working DOCX

В рабочей версии источник добавляется как Word comment к значению.

Пример видимого текста:

```text
Оплачен
```

Комментарий:

```text
Источник: сообщение в проектном чате от 31.08.2026.
Статус подтверждения: provisional.
Для официального факта поступления требуется сверка с банком/учетной системой.
```

## Clean DOCX

Комментарии удаляются.

Видимый текст не должен содержать:
- "по данным чата";
- "по контексту";
- "из памяти";
- технические идентификаторы источников.

## sources.json

Все source records выгружаются отдельно. Это позволяет:
- проводить аудит;
- повторно собирать следующий ОСП;
- понимать, почему поле было заполнено;
- заменять provisional-факт на confirmed без ручного поиска старой переписки.
