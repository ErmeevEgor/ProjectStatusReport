# Project Status Report v0.9.0 — основной веб-сценарий

Версия 0.9.0 упрощает скилл до одного основного процесса: работа через веб-нейросеть (например, ChatGPT) с проектной папкой Google Drive и предыдущим ОСП в Confluence Storage Format.

## Что подаётся на вход

Обязательный набор:

1. ссылка на папку проекта в Google Drive;
2. файлы проекта/контекста в этой папке;
3. `report-data.json` и `sources.json` в той же папке, если state уже создан ранее;
4. предыдущий ОСП в формате хранения Confluence XML/XHTML;
5. при необходимости — дополнительные файлы, приложенные прямо в чат, и ссылки на проектные источники.

Предыдущий Storage Format является структурным шаблоном следующего ОСП.

## Что должно получиться

В Google Drive, в той же папке проекта:

- обновлённый `report-data.json`;
- обновлённый `sources.json`.

В ответе веб-нейросети:

- `ОСП_<номер>_Confluence_Storage_Format.xml`.

XML пользователь вручную вставляет на новую страницу Confluence через Source Editor.

Сам XML **не нужно загружать в Google Drive**, если пользователь отдельно этого не попросил.

## Чего больше нет в основном процессе

- DOCX;
- working/clean DOCX;
- правило «ровно 4 страницы»;
- конвертация DOCX → Confluence;
- локальный `source-manifest.json`;
- автоматическая публикация в Confluence;
- отдельная ветка локального агента как основной сценарий.

## Рекомендуемый запрос

```text

https://github.com/ErmeevEgor/ProjectStatusReport.

Сформируй актуальный ОСП.

Папка проекта в Google Drive:
<ССЫЛКА_НА_ПАПКУ>

В папке находятся проектные материалы, report-data.json и sources.json.
Дополнительные изменения проекта могут быть приложены к сообщению или указаны ссылками.

Предыдущий ОСП приложен в Confluence Storage Format XML.
Используй его как основной структурный шаблон следующего ОСП.
Сохрани таблицы, колонки, группировку, макросы, native dates и Handy Status.
Не используй DOCX.

На выходе:

2. обнови sources.json в той же папке Google Drive;
3. верни в чат файл ОСП_<номер>_Confluence_Storage_Format.xml для ручной вставки в Confluence.

```

## Как обновляется состояние проекта

`report-data.json` — текущее нормализованное состояние проекта и ОСП.

`sources.json` — реестр источников и доказательная трассировка.

Это постоянные файлы проекта. При следующем запуске они читаются, сверяются с новыми материалами и обновляются.

Если файлы уже существуют в Drive, их нужно обновлять **на месте**, а не создавать новые копии вида `report-data (1).json`.

Если state-файлов нет, но есть предыдущий ОСП и проектные материалы, state можно восстановить консервативно и создать впервые.

## Как используется предыдущий ОСП

Из предыдущего XML берутся:

- номер и дата прошлого отчёта;
- незакрытые риски, вопросы и действия;
- структура разделов;
- таблицы и колонки;
- группировка строк;
- native Confluence-макросы;
- пул доступных Handy Status ID.

Новый отчёт обычно получает номер `N+1`, а отчётный период строится от даты предыдущего ОСП до текущей даты отчёта.

## Источники проекта

Приоритет договорного baseline:

1. подписанный договор;
2. подписанное ДС;
3. официальный документ той же юридической силы, изменяющий baseline.

Оперативные источники могут обновить факт выполнения, но не должны сами по себе менять договорный объём, бюджет, сроки или условия оплаты.

## Статусы работ

Только четыре видимых статуса:

| Статус | Прогресс |
|---|---:|
| Не начато | 0% |
| В работе | 50% |
| На согласовании | 90% |
| Выполнено | 100% |

Прогресс считается по бюджету, а не по количеству задач.

## Handy Status

Нельзя придумывать numeric ID Handy Status.

Для следующего отчёта используются только ID, которые уже присутствуют в предыдущем Storage Format и однозначно относятся к нужному статусу в том же смысловом домене.

Если безопасного ID для нового состояния нет, выводится обычный текст статуса и XML-комментарий `HANDY_STATUS_ID_REQUIRED`, а не фиктивный макрос.

## Native dates

Отдельные даты в таблицах и полях должны оставаться нативными Confluence dates:

```xml
<time datetime="2026-10-07" />
```

Дата не придумывается, если её нет в источниках.

## Если Google Drive не удалось обновить

Нейросеть не должна писать, что файлы сохранены, если запись не состоялась.

В этом случае она:

- всё равно возвращает XML;
- возвращает новые `report-data.json` и `sources.json` как файлы в чат;
- явно сообщает, что Drive не обновлён.
