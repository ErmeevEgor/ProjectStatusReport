# Правила статусов

## Работы

Использовать четыре расчетных состояния:

- `COMPLETED`
- `APPROVAL`
- `IN_PROGRESS`
- `NOT_STARTED`

Видимый русский текст может быть более точным, но коэффициент должен маппиться в одно из этих состояний.

## Риски

- `Открыт`
- `В обработке`
- `Реализован`
- `Закрыт`

Если риск реализовался, его тип лучше изменить на `ПРОБЛЕМА`, если это улучшает читаемость.

## Оплаты

- `Оплачен`
- `Подтвержден`
- `Не оплачен`
- `Требует подтверждения`
- `Не наступил срок`

## Подтверждение факта

- `confirmed`
- `provisional`
- `missing`
- `conflict`

`provisional` допустим во внутренней модели, но в основном отчете должен быть преобразован в нормальный управленческий статус без технических слов.

Для оплат используется отдельное структурное поле `fact_evidence_level`:

- `official` → факт из официального финансового источника, статус `Оплачен`;
- `project_confirmed` → `Факт поступления подтвержден`, статус `Подтвержден`;
- `provisional` → `Требует подтверждения`;
- `missing` → `Не наступил срок`, `Не оплачен` или `Требует подтверждения`
  по договорному сроку.

Если поле отсутствует, runtime поддерживает старые `status` и
`requires_confirmation`, но новые отчеты должны использовать
`fact_evidence_level` как source of truth.
