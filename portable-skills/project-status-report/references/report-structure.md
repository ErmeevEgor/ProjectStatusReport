# Структура ОСП v0.6

## Страница 1. Общие сведения

### Паспорт — только вертикальный формат

| Поле | Значение |
|---|---|
| Заказчик | ... |
| Проект | ... |
| Руководитель проекта от Исполнителя | ... |
| Руководитель проекта от Заказчика | ... |
| Основание | Договор ...; ДС ...; ДС ... |
| Номер отчета | № ... |
| Отчетный период | от даты предыдущего ОСП до даты текущего ОСП, если определяется надежно |

`Заказчик` и `Проект` никогда не размещаются в параллельных колонках.

### Сводные данные по проекту

| Поле | Значение | Поле | Значение |
|---|---|---|---|
| Дата начала проекта | `report.project_start_date` | Текущий этап проекта | `report.stage_name` |
| Утвержденный бюджет | runtime | Освоено / прогресс | runtime |

### План и статус этапов / дополнительных соглашений

Одна строка на активный договорный этап/ДС:

| Этап / ДС | План начала | Факт начала | Откл. | План завершения | Факт завершения | Откл. | Статус | Бюджет | Освоено / % |
|---|---|---|---|---|---|---|---|---:|---:|

Используются поля `stages[].contract_reference`, `planned_start`, `actual_start`, `start_deviation`, `planned_end`, `actual_end`, `end_deviation`, `status`, `budget`.

Видимый статус строго один из: `Не начато`, `В работе`, `На согласовании`, `Выполнено`.

### Общий статус проекта

4–6 Word list items.

### План / факт оплат

Сохраняется текущая 7-колоночная таблица платежей.

## Страница 2. Данные по задачам

Договорные задачи + отдельный блок `Оперативные факты отчетного периода`. Оперативные задачи не участвуют в прогрессе. Все рабочие статусы отображаются только в четырехстатусной модели.

## Страница 3. Риски проекта

Без изменений по смыслу: таблица рисков, `Ключевой вывод по рискам`, при необходимости `Финансовое наблюдение`.

## Страница 4. Ключевые вопросы и проблемы

Подзаголовок `Контроль состояния проекта` вместо `Health check`, затем таблица открытых вопросов и `Следующий контрольный ориентир`.
