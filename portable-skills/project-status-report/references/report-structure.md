# Структура ОСП v0.7

## Приоритет шаблона

Если по проекту есть предыдущий ОСП, он является основным шаблоном структуры следующего отчета.

Сохраняются без переизобретения:
- порядок страниц и разделов;
- названия разделов, если они не конфликтуют с обязательными правилами текущего скилла;
- состав, порядок и смысл колонок таблиц;
- группировка строк;
- ширины колонок и общая визуальная иерархия.

В новом ОСП обновляются факты, статусы, сроки, риски, оплаты и расчет прогресса. Структура меняется только если изменился договорный объем, пользователь явно попросил новую структуру или предыдущая структура конфликтует с обязательным правилом скилла.

Если предыдущего ОСП нет, используется встроенный fallback-шаблон ниже.

## Страница 1. Общие сведения — fallback

### Паспорт — только вертикальный формат

| Поле | Значение |
|---|---|
| Заказчик | ... |
| Проект | ... |
| Руководитель проекта от Исполнителя | ... |
| Руководитель проекта от Заказчика | ... |
| Основание | Договор ...; ДС ...; ДС ... |
| Номер отчета | № ... |
| Отчетный период | от даты предыдущего ОСП до даты текущего ОСП, если определяется надежно |

`Заказчик` и `Проект` никогда не размещаются в параллельных колонках.

### Сводные данные по проекту

| Поле | Значение | Поле | Значение |
|---|---|---|---|
| Дата начала проекта | `report.project_start_date` | Текущий этап проекта | `report.stage_name` |
| Утвержденный бюджет | runtime | Освоено / прогресс | runtime |

### План и статус этапов / дополнительных соглашений

Одна строка на активный договорный этап/ДС:

| Этап / ДС | План начала | Факт начала | Откл. | План завершения | Факт завершения | Откл. | Статус | Бюджет | Освоено / % |
|---|---|---|---|---|---|---|---|---:|---:|

Используются поля `stages[].contract_reference`, `planned_start`, `actual_start`, `start_deviation`, `planned_end`, `actual_end`, `end_deviation`, `status`, `budget`.

Видимый статус строго один из: `Не начато`, `В работе`, `На согласовании`, `Выполнено`.

### Общий статус проекта

4–6 Word list items.

### План / факт оплат

Сохраняется текущая 7-колоночная таблица платежей.

## Страница 2. Данные по задачам

При наличии предыдущего ОСП таблица переносится из него как структурный шаблон. Для того же договорного объема не менять колонки и группировку без необходимости.

Fallback-таблица договорных задач:

| Код задачи | Наименование | Задача | Статус | Бюджет | Освоено | План начала | План завершения | Факт | Комментарий |
|---|---|---|---|---:|---:|---|---|---|---|

Правила:
- `Код задачи` — код ФР/договорной строки, а не порядковый номер таблицы;
- `Наименование` — человекочитаемое название требования/работы;
- `Задача` — конкретный договорный подэтап/результат, например «Составление и согласование Листа требований» или «Реализация и сдача разработанного функционала»;
- `План начала` и `План завершения` всегда отдельные колонки;
- `Факт` содержит подтвержденную фактическую дату завершения/передачи, если она есть;
- не объединять `Наименование` и `Задача`, когда оба значения доступны.

После договорной таблицы может идти отдельный блок `Оперативные факты отчетного периода`. Оперативные задачи не участвуют в прогрессе. Все рабочие статусы отображаются только в четырехстатусной модели.

## Страница 3. Риски проекта

Без изменений по смыслу: таблица рисков, `Ключевой вывод по рискам`, при необходимости `Финансовое наблюдение`.

## Страница 4. Ключевые вопросы и проблемы

Подзаголовок `Контроль состояния проекта` вместо `Health check`, затем таблица открытых вопросов и `Следующий контрольный ориентир`.
