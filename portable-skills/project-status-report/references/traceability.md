# Трассировка источников

## Цель

Клиентский XML ОСП должен выглядеть как обычный управленческий отчёт. Техническая доказательная трассировка хранится отдельно в persistent state.

## Source record

Рекомендуемый формат:

```json
{
  "id": "src-001",
  "type": "additional_agreement",
  "name": "ДС №1",
  "date": "2026-06-25",
  "reference": "п. 3.2 / Приложение 1",
  "note": "Стоимость этапа 1 010 000 руб.",
  "confidence": "confirmed"
}
```

## `sources.json`

`sources.json` хранит постоянный реестр источников проекта.

Правила:

- сохранять стабильные ID уже известных источников;
- добавлять новую запись только для нового источника/версии доказательства;
- хранить дату, ссылку/идентификатор, краткое назначение и confidence;
- не записывать секреты, токены доступа или внутренние connector credentials;
- не удалять старый источник, если он нужен для объяснения исторического или перенесённого факта.

## `report-data.json`

Материальные поля, задачи, оплаты, риски и открытые действия должны ссылаться на source IDs, которыми они подтверждаются.

## Client-visible XML

В видимом XML не должно быть:

- внутренних source ID;
- confidence labels;
- connector/tool names;
- «по памяти LLM»;
- «по контексту»;
- других служебных пояснений.

Если существует конфликт одинаково сильных источников, конфликт отражается в state/open items нейтрально, без скрытого выбора одного факта.
