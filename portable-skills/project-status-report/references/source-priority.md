# Приоритет и сверка источников

## Базовый порядок

1. Подписанный договор.
2. Подписанное дополнительное соглашение.
3. Акт / УПД / официальный документ приемки.
4. Банк / учетная система / официальный платежный документ.
5. Более поздний официальный документ той же юридической силы.
6. Предыдущий утвержденный ОСП — для continuity.
7. Task tracker / Bitrix24 / Confluence / Jira.
8. Утвержденный протокол встречи.
9. Проектная переписка.
10. Текущий контекст LLM / проектного чата.

## Правила

### Договорный план

Сроки, стоимость, состав работ, результаты и условия оплаты нельзя заменять данными переписки, если договор/ДС уже подписан.

### Текущий факт

Факт выполнения может подтверждаться:
- актом;
- статусом задачи;
- протоколом;
- перепиской;
- текущим проектным контекстом.

Сила подтверждения должна храниться в metadata.

Task tracker является авторитетным источником оперативного факта, но никогда не
является авторитетным источником договорной структуры строк страницы 2, бюджета
или baseline-дат, если существует подписанный договор или ДС.

### Оплаты

Фраза в чате «оплатили» — рабочий факт, но не подтверждение поступления денег.

Если официального подтверждения нет:
- `actual_status = "Требует подтверждения"`;
- source metadata хранит сообщение;
- в итоговом сообщении пользователю указывается, что дату поступления нужно подтвердить.

### Конфликт

Если два источника одинакового уровня противоречат:
- не выбирать молча;
- пометить `confidence = "conflict"`;
- вывести нейтральное значение;
- добавить конфликт в список данных для подтверждения.

### Дата

Более поздний источник не автоматически сильнее подписанного документа: он сильнее только для текущего факта, но не для изменения договорного baseline без оформленного изменения.
